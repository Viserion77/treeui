<Title>Accessibility</Title>

Accessibility is part of the TreeUI contract, not a later pass. The rules themselves — native
semantics first, the keyboard model, focus trapping and restoration, minimum target size, and the
states every interactive component owes beyond the happy path — are the "Accessible by default" and
"Visual interaction feedback" practices, and each one names the components that follow it on
<a target="_top" href="./?path=/docs/foundation-practices--docs">Practices</a>.

This page is about how that contract stays true. Every change runs `pnpm lint`, `pnpm typecheck`,
and `pnpm test`; stories run through `@storybook/addon-a11y` and `@storybook/addon-vitest`, so an
axe violation or a broken interaction fails in the same pass as the unit tests. Playwright smoke
tests cover the flows where focus has to move correctly — the modal's focus trap and Escape
handling, and keyboard navigation inside the date picker.

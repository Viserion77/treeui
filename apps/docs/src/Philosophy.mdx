<Title>Philosophy</Title>

TreeUI is designed for mature SaaS, dashboards, admin panels, and internal tools that need polish
without visual noise. It is optimized for two kinds of clarity at once: **visual clarity** for the
people using the product, and **development clarity** for the teams building it.

Four pillars guide every component and every review. They are listed — alongside the named practices
that enforce them and the components that follow each one — on
<a target="_top" href="./?path=/docs/foundation-practices--docs">Practices</a>, which renders from
the canonical `docs/ai/practices.json`.

Breadth is not the goal; quality, portability, and a public foundation that later packages can extend
are. Foundations stay semantic and framework-agnostic, so the React package and any future Svelte or
Web Component wrapper inherit the same contract instead of redefining it.

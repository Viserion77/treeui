What TreeUI plans to add, and the rule it uses to decide. For what already ships, see the

## Shipped

Milestones 1–3 are complete and part of the public surface:

- **Milestone 1 — Application primitives**: `TStat`, `TMultiSelect`, `TNumberInput`, `TSelectableList`, `TTreeView`, `TSteps` / `TStepper`, `TToggleGroup`.
- **Milestone 2 — App shell & layout**: `TSidebar` / `TNavMenu`, `TNavbar` / `TAppBar`, `TContainer`, `TGrid`, `TStack`.
- **Milestone 3 — Routing, cards & inline links**: `TNavMenu` RouterLink support, `TCard` `title` prop and `#actions` slot, `TCard variant="inset"`, `TLink`.
- **Data visualization**: `TChart`, `TSparkline`, `TDonutChart`, sharing a framework-agnostic geometry engine in `@treeui/utils` and the `--tree-color-chart-*` palette.
- **React package**: `@treeui/react` ships the core primitives on the same tokens and `t-*` classes.

## Planned

| Item | Notes |
|---|---|
| `TCarousel` | Focused media and card browsing patterns. Not started. |
| `@treeui/react` parity | Grow the React package beyond the core primitives, same tokens and class names. In progress. |
| Right-to-left layout | Logical properties across the component CSS plus an RTL story axis. Not started. |
| Motion token expansion | More duration/easing steps and a reduced-motion contract. Not started. |
| Theme builder | Visual token editor on top of `@treeui/tokens`. Exploratory. |
| Additional framework packages | `@treeui/svelte` and Web Components reusing the same tokens, naming, and accessibility guidance. Exploratory. |

## Table direction

`TTable` stays intentionally lean and focused on structured listing. Pagination, filters,
toolbars, bulk actions, and data fetching stay composable outside the table, with
`TPagination` used separately when needed.
